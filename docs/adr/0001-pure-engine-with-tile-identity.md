# Pure functional engine with stable Tile identity

We need the canvas renderer to animate Tiles sliding and merging across a Move. The obvious representation for the Grid is a plain `number[][]`, but diffing two number grids to infer which Tile went where is ambiguous — in particular, deciding which of two merging Tiles "survives" its id can't be recovered from before/after values alone. Instead, the Grid is `Tile[]`, where each Tile carries a stable unique id assigned at spawn and preserved across Moves; the engine's `applyMove(grid, direction)` is a pure function that returns new state (new Tile positions/ids, score gained, spawned Tile) without mutating its input. This also gives the engine trivial unit-testability (assert on return values, no mutable setup/teardown) and lets the renderer animate directly from "old state → new state" without any inference step.
